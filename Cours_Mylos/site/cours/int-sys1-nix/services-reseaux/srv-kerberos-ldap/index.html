Introduction

Utilisation de l’annuaire LDAP comme base de données au service Kerberos. Cette configuration permettra de simplifier la configuration de la réplication de la base kerberos. Mais également, de centraliser la gestion des utilisateurs du domaine dans l’annuaire.

Configuration du service d’annuaire LDAP

Installation des paquets

$ sudo apt-get install krb5-kdc-ldap schema2ldif

Ajout du schéma Kerberos à l’annuaire

Configuration du service kerberos

Configuration des accès à l’annuaire par kerberos

$ sudo vim /etc/krb5.conf

[libdefaults]
        default_realm = ANTITERRE.LAN

...

[realms]
        ANTITERRE.LAN = {
                kdc = kdc1.antiterre.lan
                admin_server = kdc1.antiterre.lan
                default_domain = antiterre.lan
                database_module = openldap_ldapconf
        }
        
...

[domain_realm]
        .antiterre.lan = ANTITERRE.LAN
        antiterre.lan = ANTITERRE.LAN
...
        
[login]
	krb4_convert = true
	krb4_get_tickets = false

[dbdefaults]
        ldap_kerberos_container_dn = cn=kerberos,dc=antiterre,dc=lan

[dbmodules]
        openldap_ldapconf = {
                db_library = kldap
                ldap_kdc_dn = "cn=admin,dc=antiterre,dc=lan"

                # this object needs to have read rights on
                # the realm container, principal container and realm sub-trees
                ldap_kadmind_dn = "cn=admin,dc=antiterre,dc=lan"

                # this object needs to have read and write rights on
                # the realm container, principal container and realm sub-trees
                ldap_service_password_file = /etc/krb5kdc/service.keyfile
                ldap_servers = ldap://ldap1.antiterre.lan
                ldap_conns_per_server = 5
        }

 [logging]
         kdc = SYSLOG:INFO:DAEMON
         admin_server = SYSLOG:INFO:DAEMON

Création du domaine kerberos

$ sudo kdb5_ldap_util -D  cn=admin,dc=antiterre,dc=lan \

Problèmes connus

Ordre de démarrage des processus lorsque la gestion des services par initd

Lors que le serveur d’authentification est redémarré, le service kdc n’est pas démarré?

  • Vérification de la présence de processus.

    La commande devrait afficher les 2 processus ci-dessous

$ ps -ef | grep -w 'kadmind\|krb5kdc'

root       743     1  0 10:31 ?        00:00:00 /usr/sbin/kadmind
root       747     1  0 10:31 ?        00:00:00 /usr/sbin/krb5kdc

  • Démarrage des services kerberos.

    Après le démarrage manuel des services, la commande ps doit afficher les 2 processus.

$ sudo invoke-rc.d krb5-kdc start
$ sudo invoke-rc.d krb5-admin-server start

$ ps -ef | grep -w 'kadmind\|krb5kdc'

root       743     1  0 10:31 ?        00:00:00 /usr/sbin/kadmind
root       747     1  0 10:31 ?        00:00:00 /usr/sbin/krb5kdc

  • Activer la journalisation de kerberos[[7]]

    A la fin du fichier /etc/krb5.conf sur le serveur d’authentification ajouter les lignes suivantes:

 [logging]
         kdc = SYSLOG:INFO:DAEMON
         admin_server = SYSLOG:INFO:DAEMON

  • Redemmarrer le serveur d’authentification

    Les processus kadmind et krb5kdc écrivent des informations dans le journal /var/log/syslog.

  • Si les services Kerberos démarrent avant le service ldap, revoir l’ordre de démarrage des processus.\Renommer le script de démarrage du service ldap (S10slapd).

$ ls -1 /etc/rc2.d/
