Introduction

Un conteneur LXC sans privilège est un conteneur s’exécutant dans le contexte d’un utilisateur non-root.

Définition

  • subuid
SUBUID(5)                File Formats and Conversions

NAME
       subuid - the subordinate uid file

DESCRIPTION
       Each line in /etc/subuid contains a user id and a range of suboridinate
       user ids that user is allowed to use. This is specified with three
       fields delimited by colons (“:”). These fields are:

       ·   login name

       ·   numerical subordinate user ID

       ·   numerical subordinate user ID count

       This file specifies the user IDs to be that each user may use with the
       newuidmap command that ordinary users can use to configure uid mapping
       in a user namespace.

       Multiple ranges may be specified per user ID.

Configuration

Définir des ids et gids subordonnées

$ grep ${USER} /etc/sub* 2>/dev/null
/etc/subgid:dhu:100000:65536
/etc/subuid:dhu:100000:65536

sudo usermod --add-subuids 100000-165536 $USER
sudo usermod --add-subgids 100000-165536 $USER

Après la commande usermod, ouvrir une nouvelle session pour prendre en compte de modification

Autorisation du réseau pour l’utilisateur

$ cat /etc/lxc/lxc-usernet 
# USERNAME TYPE BRIDGE COUNT
dhu veth virbr0 10
dhu veth lxcbr0 10

Configuration par défaut du conteneur

  • Créer le dossier ~/.config/lxc
$ mkdir -p ~/.config/lxc
  • Créer le fichier ~/.config/lxc/default.conf
$ vim ~/.config/lxc/default.conf 

lxc.net.0.type = veth
lxc.net.0.link = lxcbr0
lxc.net.0.flags = up
lxc.net.0.hwaddr = 00:16:3e:xx:xx:xx
lxc.idmap = u 0 100000 65536
lxc.idmap = g 0 100000 65536

Le fichier ~/.config/lxc/default.conf prend comme base le contenu du fichier /etc/lxc/default.conf.

pour plus de détail man lxc.container.conf

Création d’un conteneur sans privilège

$ lxc-create -t download -n p1 -- -d ubuntu -r bionic -a amd64

$ tree -L 2 .local/share/lxc/ 
.local/share/lxc/
├── lxc-monitord.log
└── p1
    ├── config
    └── rootfs

ATTENTION

Les dossiers ~/.local et ~/.local/share doivent avoir le droit x pour tous le monde.

huguenindo@mc0-0315-dhu:~$ chmod go+x ~/.local
huguenindo@mc0-0315-dhu:~$ chmod go+x ~/.local/share

huguenindo@mc0-0315-dhu:~$ ls -ld ~/.local
drwx--x--x 3 huguenindo huguenindo 4096 nov  9 15:12 /home/huguenindo/.local
huguenindo@mc0-0315-dhu:~$ ls -ld ~/.local/share
drwx--x--x 25 huguenindo huguenindo 4096 fév 19 09:59 /home/huguenindo/.local/share

Lors de problème avec un conteneur, il est possible de démarrer le conteneur avec une journalisation.

huguenindo@mc0-0315-dhu:~$ lxc-start -n p1 --logfile p1.log
huguenindo@mc0-0315-dhu:~$ cat p1.log
lxc-start p1 20190219093140.213 ERROR    start - start.c:print_top_failing_dir:125 - Permission denied - 
   Could not access /home/>huguenindo/.local. Please grant it x access, or add an ACL for the container root
lxc-start p1 20190219093140.213 ERROR    sync - sync.c:__sync_wait:62 - An error occurred in another process 
   (expected sequence >number 3)
lxc-start p1 20190219093140.213 ERROR    lxccontainer - lxccontainer.c:wait_on_daemonized_start:842 - 
    Received container state >"ABORTING" instead of "RUNNING"

Visualisation des processus du conteneur sur l’hôte

Dans le conteneur:

ubuntu@p1:~$ cat < /dev/zero > /dev/null

Sur l’hôte:

huguenindo@mc0-0315-dhu:~$ ps -ef | grep cat
...
101000    9027  9013 99 10:47 pts/4    00:04:11 cat
...
